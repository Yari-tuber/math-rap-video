# 音频：出歌、对时间、挑版本

## 一、出歌：两条路，原理一样

先问用户：**「你有没有音乐模型的 API？」**

### 有 API：让 skill 直接生成

现在支持 **ElevenLabs Music**（Starter 档起有接口；Creator 档起生成的歌可以商用、上流媒体，以官方 Music Terms 为准）。

```
python mrv.py key elevenlabs                                   # 粘贴密钥，不显示；或 --file <存密钥的文件>
python mrv.py music <作品目录> --api elevenlabs --takes 2       # --preset chant（念唱，默认）/ boombap（吐字最清楚）
```

- 每版约 1000 额度（70 秒的歌）。**生成前告诉用户要花多少。**
- 它按段落给时长（每句一小节），所以比网页生成更容易做到「一句一小节」、人声准时进。
- 密钥存在 `~/.math-rap-video/keys.json`，也可以用环境变量 `ELEVENLABS_API_KEY`。不要写进作品目录、不要打印。

想接别的平台：照 `scripts/music_api/elevenlabs.py` 写一个插件，在 `scripts/music_api/__init__.py` 的 `PROVIDERS` 里加一行。

### 没有 API：用提示词去网页生成

`mrv.py lyrics` 已经在作品目录的 `给音乐模型/` 里写好了各平台的说明，歌词已经填进去：

| 文件 | 平台 | 说明 |
|---|---|---|
| `Suno.md` | suno.com | 设置清单、三套风格词、排除词、歌词框。v6 要 Pro 档；免费号只有 v6-mini、不能商用、新号基本不能下载。**按官方文档和社区经验写的，作者没有实测** |
| `海绵音乐.md` | haimian.com（字节，免费，国内直连） | 曲风选标签，歌词只留段落名 |
| `Mureka.md` | mureka.cn | `[Hook]` 已换成 `[Chorus]`，风格描述在 300 字以内 |
| `通用.md` | 任何平台 | 英文风格串（在 ElevenLabs 上实测过）+ 中文说法 |
| `送唱版歌词.txt` | — | 只有段落名和歌词，哪里都能贴 |

让用户生成 2–3 首，下载 mp3 回来。

### 「送唱版」是什么

`lyrics.md` 是给人看、上屏的，可以写 `3²`、`1/12`、`50%`。音乐模型看到阿拉伯数字和符号常常乱读，所以 `mrv.py lyrics` 另外生成一份唱的：数字写成汉字（`3² → 三的平方`、`1/12 → 十二分之一`）、去掉圆括号（Suno 会把圆括号里的字唱成和声）、去掉引号书名号、按 `读音替换.json` 换掉多音字和生僻字。两份句数、顺序完全一样：对齐用唱的那份，字幕显示 `lyrics.md` 原文。

多音字唱错了：作品目录写 `读音替换.json`，`{"原词": "同音字"}`，词写两个字以上，免得误伤别处。例：`{"吴会": "吴快", "孤鹜": "孤雾"}`。

### 实测经验（ElevenLabs 7 首、两首歌）

- **旋律越强，吐字越糊。** 想好听就多出几版，挑口诀最清楚的，不挑最好听的。
- **同样的输入，结果不一样。** 有一首歌 5 版里 2 版人声晚进了两小节，后面的歌词全被挤。一次至少 2–3 版。
- **节奏靠字数控制。** 一句一小节主要靠每句 11–15 个字。
- **「是」后面跟数字容易听错**：「斜边是五」被听成「斜边十五」，写成「斜边等于五」。`mrv.py lyrics` 的体检会提醒。

## 二、对时间：`mrv.py song`

```
python mrv.py song <作品目录> --song 第一首.mp3 第二首.mp3
```

不写 `--song` 就用作品目录 `歌/` 里的所有音频（接口生成的歌就在那里）。每一版依次：

1. **分人声**（demucs，CPU 上一首 1–2 分钟；有缓存，重跑很快）。
2. **逐字强制对齐**：按送唱版，把每个字对到第几秒唱（Qwen3-ForcedAligner-0.6B，阿里通义，Apache-2.0，可以商用；第一次自动下载约 1.8 GB）。
3. **算节拍和每句每字的时间**，写成 `timing_<版本名>.json`。
4. **检查**：
   - 某句时长短得离谱，或者几乎没有人声 → 很可能没唱；
   - 字被挤成一团 → 漏唱或唱太快；
   - 人声比约定的两小节前奏晚进 → 后面会被挤；
   - 整体被压缩。
5. **挑一版**：可用的优先 → 口诀那几句没问题的优先 → 问题句少的 → 落在小节头的句子多的 → 人声进得准的。写成 `timing.json`，理由和要用户重点听的句子写进 `状态.json`。

实测：只用强制对齐的结果，和「识别 + 强制对齐」合起来的结果几乎一样（24 句里 22 句起点完全相同，另外 2 句差 0.08 秒），所以观众不用自己去识别字幕。

**结论是「建议换一版」（退出码 3）不是程序错误。** 不要改代码，也不要改歌词去迁就；告诉用户哪几句有问题，再生成一两版放进 `歌/` 重跑，或者用户接受这版。换成另一版：`python mrv.py pick <作品目录> 生成_02`。

### 歌词从哪来

- 有 `lyrics.md` 就用它。
- 没有，但 mp3 里嵌着歌词（Suno 导出的通常有）：自动读出来写成 `lyrics.md` 草稿。**一定要核对**：Suno 会跳过、重复、改动某几句，`lyrics.md` 必须和实际唱的一字不差。

### 环境

对齐要 torch + transformers（5.13 以上，所以 Python 3.11 以上），分人声要 demucs。`mrv.py doctor --fix` 会建一个独立环境装好。已经有装好的环境：

```
python mrv.py doctor --python <有 torch 和 transformers 的 python.exe> --demucs-python <有 demucs 的 python.exe> --model <本地对齐模型文件夹>
```

国内网络：先设 `HF_ENDPOINT=https://hf-mirror.com`；或者从 ModelScope 下 `Qwen/Qwen3-ForcedAligner-0.6B-hf`，用 `--model` 指过去。

### 只有讲解配音、没有节拍

普通配音（不是歌）也能用：流程一样，`mrv.py song` 检测不到节拍时，`B` 和 `beat()` 按 90 BPM 名义值算，画面照样跟着字走。
